# finanedly · база компаний

Раз в неделю скрипт собирает базу публичных компаний для игр finanedly и публикует её одним файлом `data/companies.json`.

**Источники (бесплатные):**
- **Wikidata** — лицензия CC0, можно использовать коммерчески без разрешения. Отсюда берутся название, синонимы, страна, регион, отрасль, год основания, биржа, тикер, основатели, CEO, штаб-квартира и известность (на скольких языках есть статья в Википедии).
- **SEC EDGAR** — официальная отчётность компаний из США: выручка и прибыль за последний финансовый год. Подключается, если указать e-mail (см. шаг 3).

## Что получится

| Файл | Что внутри |
|---|---|
| `data/companies.json` | Компании, прошедшие проверку. Из этого файла берут данные игры. |
| `data/review.json` | Компании с проблемами в данных: нет страны, непонятная отрасль, разные годы основания, незнакомая биржа. У каждой указана причина. |
| `data/changes.md` | Что изменилось с прошлой недели: кто добавился, кто пропал, у кого поменялся CEO или биржа. |

**Уровни сложности** считаются по числу Википедий со статьёй о компании: от 80 языков — «лёгкий», от 40 — «средний», от 20 — «сложный», меньше — «эксперт». Пороги задаются в `LEVELS` в начале скрипта.

## Как запустить (один раз, ~15 минут)

1. **Создайте репозиторий на GitHub.** Зарегистрируйтесь на github.com, если ещё нет аккаунта. Нажмите **New repository**, назовите его `finanedly-data`, выберите **Public**.
2. **Загрузите файлы.** **Add file → Upload files**, перетащите содержимое этой папки целиком, включая скрытую папку `.github`. Нажмите **Commit changes**. Если `.github` не перетаскивается, создайте файл вручную через **Add file → Create new file** с именем `.github/workflows/update-companies.yml` и вставьте туда его содержимое.
3. **(По желанию) Подключите SEC.** **Settings → Secrets and variables → Actions → New repository secret**. Имя: `SEC_CONTACT`, значение: ваш e-mail. SEC требует, чтобы автоматические запросы были подписаны контактом.
4. **Первый запуск.** Вкладка **Actions** → «Обновление базы компаний» → **Run workflow**. Первый запуск идёт 10–30 минут. Если всё прошло успешно, в папке `data/` появятся три файла.
5. **Публикация.** **Settings → Pages → Source: Deploy from a branch**, ветка `main`, папка `/ (root)`. Через минуту база будет доступна по адресу
   `https://ВАШ-ЛОГИН.github.io/finanedly-data/data/companies.json`.
   Этот адрес нужно будет вставить в код игр.

Дальше всё работает само: каждый понедельник утром база обновляется и коммитится.

## Еженедельная рутина (10–15 минут)

1. Откройте `data/changes.md` и пробегитесь глазами по изменениям.
2. Откройте `data/review.json`. Если там есть известные компании, поправьте данные прямо в Wikidata: это открытая база, отредактировать её может любой. На следующей неделе компания попадёт в игру. Заодно база станет лучше для всех.
3. Если сектор не определился из-за новой отрасли, добавьте ключевое слово в `SECTOR_RULES` в скрипте.

## Настройки

- `MIN_SITELINKS` в `.github/workflows/update-companies.yml` — порог известности. 10 даёт порядка нескольких тысяч компаний. Если компаний слишком много или запуск падает по времени, увеличьте его.
- `SECTOR_RULES` — как отрасли Wikidata сводятся к секторам игры.
- `EXCHANGES` — русские короткие названия бирж.

## Защита от сбоев

- Если Wikidata не отвечает, скрипт делает несколько повторов с паузой.
- Если компаний вдруг стало меньше 70% от прошлого раза, файл не перезаписывается и запуск помечается как ошибка. Старая база остаётся рабочей.
- GitHub отключает расписание в репозиториях без активности дольше 60 дней. Еженедельные коммиты с обновлённой базой сами держат репозиторий активным.

# Цитаты

Второй скрипт, `scripts/collect_quotes.py`, запускается каждый вторник, после обновления базы компаний. Его можно запустить и вручную: **Actions → «Сбор цитат-кандидатов» → Run workflow**. Первый раз запускайте его только после того, как появится `data/companies.json`.

**Откуда цитаты.** Скрипт берёт из Wikidata основателей и CEO компаний из базы, у которых есть страница в англоязычном **Wikiquote**. Со страницы забираются только цитаты с указанным источником. Разделы «Disputed» (спорные), «Misattributed» (ложно приписанные), «Attributed» и «Quotes about…» (цитаты о человеке) пропускаются.

**Цитаты не попадают в игру сами.** Все новые записи появляются в `data/quotes.json` со статусом `"new"`. В игру идут только записи со статусом `"ok"`.

## Как проверять цитату

У каждой записи есть подсказки:
- `secondary_source: true` — источник вторичный («As quoted in…», то есть цитату пересказал журналист). Такие проверять тщательнее, а лучше найти первоисточник.
- `mentions_company: true` — в цитате есть название компании, и она сразу выдаёт ответ. Такую цитату либо отклоняем, либо заменяем название на «…».
- `wikiquote` — ссылка на страницу, откуда взята цитата.

Порядок проверки:
1. Найти первоисточник: письмо, речь, интервью, книгу. Вставить ссылку в `primary_url`.
2. Добавить русский перевод в `quote_ru`.
3. Поменять `status` на `"ok"`. Если цитата не подошла, поставить `"no"`, тогда скрипт больше её не предложит.

Править можно прямо на GitHub: открыть файл, нажать карандаш, сохранить. Ваши правки скрипт при следующих запусках не трогает, он только добавляет новых кандидатов.

**Лицензия.** Wikiquote распространяется по CC BY-SA, а сами цитаты принадлежат их авторам. В игре показываем короткую цитату, автора и ссылку на первоисточник.
